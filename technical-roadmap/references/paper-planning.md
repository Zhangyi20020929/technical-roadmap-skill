# 论文技术路线的内容规划

先判断用户要表达总体研究路线还是某项方法流程，使用已有材料确定节点；不按固定模板补齐研究。

## 学位论文研究路线

以研究问题或工程需求组织任务，展示材料/数据准备、并行研究、分析及最终认识之间的依赖。章节名可作为模块标签，但“第三章在第四章前”不等于第三章全部结果都输入第四章。

只在源文支持时画材料参数进入构件分析、构件结果进入结构评价等跨尺度关系。不同试验共用对象可以并列，共用输入用母线分配，某一支专属的边界条件不要经共同母线传给其他支。若一个章节包含试验、拟合和验证，可在该模块内展开，无须把整章缩成一个含糊节点。

## 研究论文方法流程

围绕研究对象、数据/样本、方法操作、分析产物和证据组织：例如原始数据进入清洗，再进入特征计算；两个方法独立分析同一数据时画成并行。引言、方法、结果、讨论是文章结构，不是流程的四个必经步骤。

对已完成研究，保持真实数据处理顺序和用户提供的结果；对拟开展方案，节点使用拟实施任务或拟形成的产物，末端写“检验假设、分析适用范围”等目标。没有实际结果时不写“证实、成功实现、显著提高”。

## 最小节点与依赖计划

在制作前内部记录下列信息，无须额外生成报告：

| 信息 | 判断依据 |
| --- | --- |
| 节点来源 | 源文中的对象、动作、方法或产物；标记关键条件与数字 |
| 输入/输出 | 谁需要谁的材料、数据、参数或证据，而非谁先被叙述 |
| 并行/串联 | 独立生成证据的任务并行；真正消费前一步输出的操作串联 |
| 标定/验证 | 拟合模型的数据属于标定；独立验证需要源文支持的独立样本或条件 |
| 反馈 | 只有明确的试验校正、迭代或反馈才画回边，并连接被修正的对应模型 |
| 结尾语气 | 计划中的预期认识与已完成研究的实际结论分开表述 |

不自动添加对照组、独立验证、敏感性分析或“完善模型”回路；它们即使常见，也不是所有论文的事实。源文不足且会改变关系时先询问；普通换行、分组和颜色可直接决定。

## 选择图式

- **纵向递进**：前一步确实提供后一步输入，如数据准备→处理→分析。
- **并行汇合**：多项试验/方法独立产生参数或证据，再综合。
- **对应矩阵**：任务、方法与指标逐列对应；行标签只说明层级，不参与箭头。
- **主模块与辅助验证**：主体分析与已有的验证/校正支线保持对应；不人为串行化。

任务图式决定连线，章节或阶段只决定分组。固定分支可用JSON工具；分支变化与交叉依赖用原生SVG。每支模块可分配不同色系，同类方法保持一致，主箭头与文字仍为黑色，不能只靠颜色表达关系。
